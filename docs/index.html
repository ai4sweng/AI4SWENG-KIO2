KIO1 – KIO2 Integration Protocol · v0.3

What goes in, and what comes back out of KIO2

KIO2 turns a failing execution into ranked suspect statements with runtime evidence, and lets a caller navigate or compare the recorded executions afterwards. This page renders the two contracts KIO2 ships as machine-checked JSON Schemas — kio2.request.schema.json and kio2.response.schema.json — as a readable reference, instead of asking an integrator to parse the raw schema files.

ℹ️

All input arrives through this one request; results reach other KIOs only through the orchestrator. Asking KIO2 for fix_recommendation is explicitly refused — per D2.6 UC-UC1-03 that step belongs to KIO7, and KIO2 supplies the evidence for it as diagnosis.slice_context.

✅

A clean run is a success, not an error. When the target runs to completion, KIO2 answers status: "ok" with defect_found: false and an empty findings list — an orchestrator step that asks "is this code broken?" has to be able to hear "no".

The one field to act on: verdict

Every bug_localization and diagnosis reply carries it, so no consumer needs to know where KIO2 sits in the workflow.

defectStatements were implicated in the failure.
cleanThe target ran to completion — nothing to localise.
inconclusiveAnalysed, but nothing could be attributed. Treat as needing human review.
kio2.request.schema.json

The execution message

Dispatched to KIO2 by the KIO1 orchestrator. This schema states what a well-formed message looks like; KIO2's runtime acceptance is deliberately more lenient — it also honours field-name aliases and inherits missing values from data.upstream — so a message that fails this schema may still be served. The schema is published for the caller's benefit, not enforced on inbound traffic.

Upstream data data.upstream

Outputs of the steps this one depends on, keyed by step id. Filled by the orchestrator. KIO2 reads the entry point, the repository root and any trace reference out of it when they are not given directly, so a declared dependency in depends_on needs no further wiring — a chain works with no extra plumbing.

What each capability additionally requires

Enforced via the schema's conditional (allOf/if/then) rules — at least one of the listed shapes must be present in data.

kio2.response.schema.json

      
The reply envelope

      

        What KIO2 returns for an execution message. Always delivered with HTTP 200 — a non-2xx
        response means the service is unavailable, a different condition from the task having failed. This is an
        enforced contract: KIO2's own test suite validates real replies from every capability,
        including both error paths, against this schema.

Capabilities & their output shapes

    
Each capability produces exactly one output shape. Click through the tabs — the color threading each one is used consistently across this page.


    

      
bug_localization
        
Records the failing run, computes a backward dynamic slice from the crash, and ranks the statements on it (FR-KIO2-05).

        
Needs: entry point + repositoryReturns: summary + ranked findings

      

      
diagnosis
        
The causal story behind the failure, read off the recording — not inferred by a model — plus a slice ready for KIO7's fix prompt.

        
Needs: same as bug_localizationOptional: a reference (passing) run

      

      
replay
        
Stateless, read-only post-mortem debugging over a trace that already exists — nothing is re-executed (FR-KIO2-02).

        
Needs: a trace_refReturns: cursor + current statement + state

      

      
trace_alignment
        
Compares control flow between two or more recorded runs (FR-KIO2-03). Identical executed-statement sequences ⇒ distance 0.

        
Needs: 2+ trace_refsReturns: pair distance, or a set matrix

Field-name aliases

      
One vocabulary, two spellings

      

        The integration protocol document uses its own names for the data payload. Both vocabularies
        are accepted at runtime, so the wording of that document does not have to be settled before wiring can start.

      🔒
      
Trace references are sandboxed. A trace_ref only resolves under
        KIO2_TRACE_DIR (default: the system temp directory). Without that check, a crafted ref could
        make KIO2 parse an arbitrary file and return its contents as "recorded state" — the adapter is the network
        edge. Bare paths are still accepted from local/library callers only.

    

  


  
  

    

      
Protocol v0.3 · docs/PROTOCOL_V03_TODO.md

      
What v0.3 asks for that isn't built yet

      

        Most of protocol v0.3 documents what the code already does (rendered above). A handful of items are written
        there as proposed and are not implemented in this contract yet — listed here so the
        schemas above aren't mistaken for the finished picture.
      

    


    

      
1 · Asynchronous processing for long analyses
proposed

      
KIO2 executes the program under analysis, so its runtime is the target's runtime — bounded
        today by KIO1's 60s request_timeout and KIO2's 45s KIO2_TRACE_BUDGET. The proposed
        fix is the 202 + job pattern already used by KIO9/KIO12: POST /execute can return
        HTTP 202 with a job object, polled via GET /jobs/{job_id} and
        GET /jobs/{job_id}/result, cancellable via DELETE.

    


    

      
2 · Closed error vocabulary
proposed

      
Today error is free text, so a caller cannot tell "no entry point" from "the
        target crashed the tracer" without parsing prose. Proposed replacement:
        {error_code, error_message, retryable}.

3 · Authentication & authorisation (profile R)
proposed

      
/execute accepts a repository path and an entry point from anyone who can reach
        it, then runs them — remote code execution by design. Profile P (no auth) stays the prototype default;
        profile R would add TLS, a bearer token or mTLS, and per-capability scopes.

    


    

      
4 · Retention & masking of recorded values
proposed

      
crash_state, replay state, and diagnosis evidence carry real values
        from the executed run, and traces are never deleted today. Proposed: a KIO2_TRACE_TTL (or an
        explicit delete endpoint) plus a sweep, and an optional value-masking reply mode.

    


    

      
5 · Smaller items
proposed
